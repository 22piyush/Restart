---- Access Modifiers -----
=========================================
## What are access modifiers?
-- Access modifiers are keywords in C# that are used to control the accessibility or visibility of a class and its members.
--In simple words, access modifiers decide who can access a class, method, property, field, etc., and from where.

## What is public?
-- public is an access modifier in C# that makes a class or its members accessible from anywhere, as long as the containing type itself is accessible.
-- In simple words, if we declare something as public, other classes can access it.

## What is private?
-- private is an access modifier in C# that restricts access to a class or its members.
-- In simple words, a private member can be accessed only inside the class where it is declared.

## What is protected?
-- protected is an access modifier that allows a member to be accessed inside its own class and inside classes that inherit from it.
--In simple words:
-protected = accessible within the class + derived/child classes.

-- Example 
class GrandParent
{
    protected int age = 50;
}

class Parent : GrandParent
{
}

class Child : Parent
{
}

class SubChild : Child
{
    public void Display()
    {
        Console.WriteLine(age); // ✅
    }
}


## What is internal?
-- internal is an access modifier in C# that allows a class or member to be accessed anywhere within the same assembly.
-- In simple words:
- internal = accessible within the same project/assembly, but not directly from another assembly.


## What is protected internal?(OR || )
-- protected internal means a member can be accessed if either of these conditions is true:
-- The code is inside the same assembly/project → internal rule
-- The code is inside a derived/child class → protected rule
-- So remember:
- protected internal = same assembly OR derived class
== It is OR, not AND.

-- Example

1. Basic example — same project
public class Parent
{
    protected internal int age = 25;
}

Now another class in the same project:

public class Test
{
    public void Display()
    {
        Parent obj = new Parent();

        Console.WriteLine(obj.age); // ✅
    }
}

Why is this allowed?

Because Test and Parent are in the same assembly/project.

Parent
   |
   | protected internal
   ↓
Same Project
   ✅ Can access

Notice that Test does not inherit from Parent.

It can still access age because of the internal part.

2. Different project + inheritance

Suppose we have two projects.

Project A
public class Parent
{
    protected internal int age = 25;
}
Project B
public class Child : Parent
{
    public void Display()
    {
        Console.WriteLine(age); // ✅
    }
}

Even though Child is in a different project, it can access age.

Why?

Because Child inherits from Parent.

So the protected rule allows access.

Project A

Parent
  |
  | protected internal
  |
  ↓
age


Project B

Child : Parent
     |
     └── can access age ✅
3. Different project + NOT inherited

Now suppose Project B has an unrelated class:

public class Test
{
    public void Display()
    {
        Parent obj = new Parent();

        Console.WriteLine(obj.age); // ❌
    }
}

This will not work.

Why?

Because:

Test is in a different assembly ❌
Test does not inherit from Parent ❌

Therefore, neither condition is satisfied.

Same assembly?       ❌
Derived class?       ❌
                         ↓
                  Cannot access



## What is private protected?(AND &&)
-- private protected is an access modifier in C# that allows a member to be accessed only inside the same assembly(project) AND only by derived classes.
-- The important word is AND.
-- private protected = same assembly AND derived class


## Difference between protected and private.

| Point                                    | `private`                                                    | `protected`                                                |
| ---------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| **Meaning**                              | Accessible only inside the class where it is declared        | Accessible inside the class and its derived/child classes  |
| **Access from same class**               | ✅ Yes                                                        | ✅ Yes                                                      |
| **Access from child class**              | ❌ No                                                         | ✅ Yes                                                      |
| **Access from unrelated class**          | ❌ No                                                         | ❌ No                                                       |
| **Access from another assembly/project** | ❌ No                                                         | ✅ Only through inheritance                                 |
| **Main purpose**                         | Hide data completely from other classes                      | Share data/behavior with child classes                     |
| **Inheritance**                          | Private members are not directly accessible by child classes | Protected members are directly accessible by child classes |
| **Encapsulation**                        | Provides stronger restriction                                | Provides controlled access for inheritance                 |
| **Common use**                           | Internal implementation details                              | Members that child classes need to use or extend           |



## Difference between internal and public.

| Point                                  | `internal`                                   | `public`                                              |
| -------------------------------------- | -------------------------------------------- | ----------------------------------------------------- |
| **Meaning**                            | Accessible within the **same assembly**      | Accessible from **anywhere**                          |
| **Same project/assembly**              | ✅ Yes                                        | ✅ Yes                                                 |
| **Different project/assembly**         | ❌ No                                         | ✅ Yes                                                 |
| **Different class in same project**    | ✅ Yes                                        | ✅ Yes                                                 |
| **Different class in another project** | ❌ No                                         | ✅ Yes                                                 |
| **Inheritance required?**              | ❌ No                                         | ❌ No                                                  |
| **Main purpose**                       | Restrict access to your own assembly/project | Make something available to other assemblies/projects |
| **Default for top-level class**        | ✅ Yes                                        | ❌ No                                                  |


## Difference between protected internal and private protected.

| Point                                    | `protected internal`                                   | `private protected`                                           |
| ---------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------- |
| **Meaning**                              | Accessible from the **same assembly OR derived class** | Accessible from the **same assembly AND derived class**       |
| **Same assembly + derived class**        | ✅ Yes                                                  | ✅ Yes                                                         |
| **Same assembly + unrelated class**      | ✅ Yes                                                  | ❌ No                                                          |
| **Different assembly + derived class**   | ✅ Yes                                                  | ❌ No                                                          |
| **Different assembly + unrelated class** | ❌ No                                                   | ❌ No                                                          |
| **Uses**                                 | `protected` **OR** `internal`                          | `protected` **AND** `internal`                                |
| **More accessible?**                     | More accessible                                        | More restricted                                               |
| **Main purpose**                         | Allow access to assembly members and derived classes   | Allow access only to derived classes within the same assembly |


## What is the default accessibility of a class?

For a **top-level class**, the default accessibility is **`internal`**.

```csharp
class Employee
{
}
```

This is the same as:

```csharp
internal class Employee
{
}
```

So the class can be accessed within the **same assembly/project**, but not directly from another assembly.

---

## What is the default accessibility of a class member?

The default accessibility of a **class member** is **`private`**.

This applies to members such as fields, methods, properties, etc.

```csharp
class Employee
{
    string name;       // private by default
    int age;           // private by default

    void Display()     // private by default
    {
    }
}
```

It is equivalent to:

```csharp
class Employee
{
    private string name;
    private int age;

    private void Display()
    {
    }
}
```

---

## Can a top-level class be `private`?

**No.**

A top-level class cannot be declared as `private`.

```csharp
private class Employee   // ❌ Not allowed
{
}
```

A top-level class can normally be:

```csharp
public class Employee
{
}
```

or:

```csharp
internal class Employee
{
}
```

If no modifier is specified, it is `internal` by default.

---

## Can a nested class be `private`?

**Yes.**

A nested class is a class declared inside another class.

```csharp
class Employee
{
    private class Address
    {
    }
}
```

In fact, a nested class is **`private` by default** if no access modifier is specified:

```csharp
class Employee
{
    class Address
    {
    }
}
```

This is equivalent to:

```csharp
class Employee
{
    private class Address
    {
    }
}
```

---

## Quick Summary

| Question                                        | Answer     |
| ----------------------------------------------- | ---------- |
| Default accessibility of a **top-level class**? | `internal` |
| Default accessibility of a **class member**?    | `private`  |
| Can a **top-level class** be `private`?         | ❌ No       |
| Can a **nested class** be `private`?            | ✅ Yes      |
| Default accessibility of a **nested class**?    | `private`  |

### Easy way to remember

```text
Top-level class
      ↓
   internal

Class member
      ↓
   private

Top-level class → private ❌

Nested class → private ✅
```

### Interview Answer

**A top-level class is `internal` by default, while class members are `private` by default. A top-level class cannot be declared as `private`, but a nested class can be private and is private by default.**



## How to restrict a class not to be accessible for any other class to consume?

First, we need to understand what **“restrict a class”** means.

If we want to prevent other classes from **directly creating an object** of a class, we can make the class's constructor `private`.

### Example

```csharp
public class Employee
{
    private Employee()
    {
    }

    public void Display()
    {
        Console.WriteLine("Employee");
    }
}
```

Now suppose another class tries to create an object:

```csharp
class Test
{
    public void Method()
    {
        Employee emp = new Employee(); // ❌ Error
    }
}
```

This is not allowed because the `Employee` constructor is `private`.

### Why does this happen?

When we write:

```csharp
Employee emp = new Employee();
```

C# needs to call the constructor:

```csharp
Employee()
```

But the constructor is:

```csharp
private Employee()
```

A `private` constructor can be accessed **only from within the `Employee` class itself**.

Therefore, another class cannot create an object of `Employee`.

---

## Important: The class is still accessible

Notice that:

```csharp
public class Employee
```

means another class **can see/reference the class**.

For example, this is valid:

```csharp
Employee emp;
```

But this is not:

```csharp
Employee emp = new Employee(); // ❌
```

So there is an important difference:

| Operation                                       | Private Constructor |
| ----------------------------------------------- | ------------------- |
| See/reference the class                         | ✅ Yes               |
| Declare a variable of that type                 | ✅ Yes               |
| Create an object using `new`                    | ❌ No                |
| Call the private constructor from another class | ❌ No                |

---

## What about inheritance?

This is an important point.

If the constructor is `private`, another class **cannot inherit from `Employee`** either.

```csharp
public class Employee
{
    private Employee()
    {
    }
}

public class Manager : Employee
{
}
```

This gives an error:

```text
❌ Manager cannot access Employee's private constructor
```

Why?

When a derived class is created, it must call a constructor of its parent class.

For example:

```csharp
Manager manager = new Manager();
```

Internally, the `Employee` constructor must also be called.

But:

```csharp
private Employee()
```

can only be accessed inside `Employee`.

Therefore:

```text
private constructor
        ↓
Other classes cannot create Employee
        ↓
Other classes cannot inherit from Employee
```

---

## What if we use a protected constructor?

If we want to prevent direct object creation but **allow inheritance**, we can use a `protected` constructor.

```csharp
public class Employee
{
    protected Employee()
    {
    }
}
```

Now this is not allowed:

```csharp
Employee emp = new Employee(); // ❌
```

But inheritance is allowed:

```csharp
public class Manager : Employee
{
}
```

```text
protected constructor
        ↓
Other classes cannot directly create Employee
        ↓
Derived classes CAN inherit Employee
```

So `private` and `protected` constructors are different.

| Constructor | Direct object creation | Inheritance |
| ----------- | ---------------------- | ----------- |
| `private`   | ❌                      | ❌           |
| `protected` | ❌                      | ✅           |
| `public`    | ✅                      | ✅           |

---

## What about `private protected`?

`private protected` can also be used when we want the constructor to be accessible only to **derived classes within the same assembly**.

```csharp
public class Employee
{
    private protected Employee()
    {
    }
}
```

A derived class in the **same assembly** can inherit:

```csharp
public class Manager : Employee
{
}
```

This works because `Manager` is:

* a derived class ✅
* in the same assembly ✅

But a derived class from another assembly cannot access this constructor.

```text
private protected
        ↓
Derived class AND same assembly
        ↓
Both conditions must be satisfied
```

### Comparison

| Constructor         | Same assembly derived class | Different assembly derived class | Normal class |
| ------------------- | --------------------------: | -------------------------------: | -----------: |
| `private`           |                           ❌ |                                ❌ |            ❌ |
| `protected`         |                           ✅ |                                ✅ |            ❌ |
| `private protected` |                           ✅ |                                ❌ |            ❌ |
| `public`            |                           ✅ |                                ✅ |            ✅ |

---

## Controlled object creation

A private constructor is commonly used when we don't want normal object creation from outside the class.

For example:

```csharp
public class Employee
{
    private Employee()
    {
    }

    public static Employee CreateEmployee()
    {
        return new Employee();
    }
}
```

Now another class cannot do:

```csharp
Employee emp = new Employee(); // ❌
```

But it can use the class's controlled method:

```csharp
Employee emp = Employee.CreateEmployee(); // ✅
```

Here, the `Employee` class itself calls its private constructor.

---

## Very Important Distinction

There are actually **two different requirements** we should not confuse:

### 1. Prevent object creation

Use a **private constructor**:

```csharp
public class Employee
{
    private Employee()
    {
    }
}
```

The class is still visible, but objects cannot be created directly.

### 2. Prevent access to the class itself

A private constructor does **not** do this.

For a top-level class, we cannot write:

```csharp
private class Employee // ❌
{
}
```

Instead, we can use `internal` if we want to restrict a top-level class to the same assembly:

```csharp
internal class Employee
{
}
```

Or we can make it a private nested class:

```csharp
public class Company
{
    private class Employee
    {
    }
}
```

Here, `Employee` can only be accessed inside `Company`.

---

## Interview Answer

**If we want to prevent other classes from directly creating an object of a class, we can make its constructor private. A private constructor can only be accessed from within the same class, so other classes cannot use the `new` keyword to create an object. It also prevents other classes from inheriting from that class because a derived class cannot access the private constructor. If we want to allow inheritance while preventing direct object creation, we can use a protected constructor.**



## How to restrict a class so that another class cannot create its instance?

**Answer:**

If we want to prevent other unrelated classes from creating an instance of a class, we can make the class constructor `protected`.

```csharp
public class Employee
{
    protected Employee()
    {
    }
}
```

Now another normal class cannot create an object:

```csharp
public class Test
{
    public void Method()
    {
        Employee emp = new Employee(); // ❌ Error
    }
}
```

But a derived class can inherit from `Employee`:

```csharp
public class Manager : Employee
{
    // ✅ Allowed
}
```

So, a `protected` constructor means:

* Normal/unrelated class → ❌ Cannot create an instance
* Derived class → ✅ Can inherit
* The class itself → ✅ Can still be used as a type

**Interview answer:**

> If we want to prevent other unrelated classes from directly creating an instance of a class while still allowing inheritance, we can declare the constructor as `protected`. A protected constructor cannot be accessed by normal classes, but it can be accessed by derived classes.

## Why can we consume an Abstract Class only through inheritance?

An **abstract class cannot be instantiated directly**. That means we cannot create its object using the `new` keyword.

```csharp
public abstract class Animal
{
    protected Animal()
    {
    }
}
```

We cannot do:

```csharp
Animal obj = new Animal(); // ❌ Cannot create object
```

Instead, we use the abstract class through **inheritance**:

```csharp
public class Dog : Animal
{
}
```

Now we can create an object of the child class:

```csharp
Dog dog = new Dog(); // ✅
```

The important point is that **an abstract class is designed to be a base/parent class**. Its purpose is to provide common members or rules that child classes can inherit and implement.

### About the constructor

The statement:

> "The constructor of an abstract class is protected."

is **not completely correct**.

An abstract class **can have a public, protected, or private constructor**. However, we still cannot directly create an object of the abstract class because the class itself is marked `abstract`.

For example:

```csharp
public abstract class Animal
{
    public Animal()
    {
    }
}
```

Even though the constructor is `public`:

```csharp
Animal obj = new Animal(); // ❌ Still not allowed
```

So the main reason is:

> **We cannot instantiate an abstract class because the class itself is abstract, not because its constructor is protected.**

### Interview answer

> An abstract class cannot be instantiated directly. It is mainly used as a base class, so we consume it through inheritance by creating objects of its derived classes. The constructor of an abstract class can have different access modifiers; it is not necessarily protected.
